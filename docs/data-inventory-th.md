# Focus Pet — ข้อมูลทั้งหมดที่ระบบเก็บ

รายการนี้ไล่จากโค้ดจริง ไม่ใช่จากความจำ ใช้เป็นเอกสารอ้างอิงสำหรับรายงานวิจัย
และสำหรับตรวจสอบว่าเก็บตรงกับที่แจ้งไว้ในหนังสือยินยอมหรือไม่

อัปเดต 22 กันยายน 2569

---

## สรุปสั้น

ระบบเก็บข้อมูล **7 ที่** ในฐานข้อมูล ทั้งหมดอยู่ใต้ `users/{uid}` ยกเว้นรายการจองรหัส

| ที่เก็บ | เก็บอะไร | เข้าไฟล์ CSV ตอนวิเคราะห์ |
|---|---|---|
| `users/{uid}` | สถานะการยินยอม + รหัสผู้เข้าร่วม | ✅ `participants.csv` |
| `users/{uid}/sessions/{id}` | เซสชันปลอดหน้าจอทีละครั้ง | ✅ `sessions.csv` |
| `users/{uid}/screenTimeDays/{date}` | เวลาหน้าจอรายวันที่กรอกเอง | ✅ `screentime.csv` |
| `users/{uid}/state/pet` | สถานะสัตว์เลี้ยง | ✅ บางส่วนใน `participants.csv` |
| `users/{uid}/state/inventory` | ไอเทมในกระเป๋า | ❌ ไม่ได้ส่งออก |
| `users/{uid}/state/achievements` | ความสำเร็จที่ปลดล็อก | ❌ ไม่ได้ส่งออก |
| `users/{uid}/state/push` | token แจ้งเตือน + กำหนดเตือนครั้งถัดไป | ❌ ไม่ได้ส่งออก |
| `participantIds/{code}` | รายการรหัสที่ถูกจองแล้ว | ❌ ไม่ได้ส่งออก |

## 1. `users/{uid}` — การยินยอมและรหัส

| ฟิลด์ | ชนิด | ความหมาย | เขียนเมื่อ |
|---|---|---|---|
| `participantId` | ข้อความ | รหัสนิรนาม เช่น `FP-K7M2N` | ตอนยินยอม |
| `participantIdSetAt` | เวลา | เวลาที่ออกรหัส | ตอนยินยอม |
| `enrolmentStatus` | ข้อความ | `undecided` / `consented` / `declined` / `withdrawn` | ตอนตอบหนังสือยินยอม |
| `consentVersion` | ข้อความ | เวอร์ชันเอกสารที่ยินยอม เช่น `2026-09-21.v1` | ตอนยินยอม |
| `consentedAt` | เวลา | เวลาที่กดยินยอม | ตอนยินยอม |
| `declinedAt` | เวลา | เวลาที่กดไม่เข้าร่วม | ตอนปฏิเสธ |
| `withdrawnAt` | เวลา | เวลาที่ถอนตัว | ตอนถอนตัว |
| `onboarded` | จริง/เท็จ | ผ่านขั้นตอนเริ่มต้นแล้วหรือยัง | ตอนตั้งชื่อสัตว์เลี้ยง |

## 2. `users/{uid}/sessions/{id}` — เซสชันปลอดหน้าจอ

**หนึ่งเอกสารต่อหนึ่งเซสชัน** นี่คือข้อมูลหลักของงานวิจัย

| ฟิลด์ | ชนิด | ความหมาย |
|---|---|---|
| `startTime` | เวลา | เวลาเริ่มเซสชัน |
| `endTime` | เวลา | เวลาจบเซสชัน |
| `actualMinutes` | ตัวเลข | ระยะเวลาที่ทำได้จริง |
| `targetMinutes` | ตัวเลข | เป้าหมายที่ตั้งไว้ (โหมดอิสระเป็น 0) |
| `completed` | จริง/เท็จ | ทำครบเป้าหรือไม่ (โหมดอิสระเป็นเท็จเสมอ) |
| `mode` | ข้อความ | `targeted` หรือ `free` |
| `source` | ข้อความ | **แหล่งที่มาของตัวเลข — ดูหัวข้อ 8** |
| `tag` | ข้อความ | ประเภทกิจกรรมที่ผู้ใช้เลือก |
| `expEarned` | ตัวเลข | EXP ที่ได้ |
| `coinsEarned` | ตัวเลข | เหรียญที่ได้ |
| `itemRewardName` | ข้อความ | ไอเทมที่ได้ (ถ้ามี) |

> **เซสชันที่สั้นกว่า 2 นาทีไม่ถูกบันทึกเลย** ทั้งที่ทำครบและที่ยกเลิก
> ถ้างานวิจัยต้องการนับความพยายามที่ล้มเหลวด้วย ต้องแก้โค้ดและแจ้งผู้เข้าร่วมใหม่

## 3. `users/{uid}/screenTimeDays/{date}` — เวลาหน้าจอรายวัน

**หนึ่งเอกสารต่อหนึ่งวัน** รหัสเอกสารคือวันที่ (`2026-09-22`) กรอกซ้ำจะทับของเดิม ไม่นับซ้ำ

| ฟิลด์ | ชนิด | ความหมาย |
|---|---|---|
| `date` | ข้อความ | วันที่รูปแบบ `YYYY-MM-DD` ตามเวลาท้องถิ่นของผู้ใช้ |
| `minutes` | ตัวเลข | จำนวนนาทีที่ผู้ใช้กรอกเอง |
| `source` | ข้อความ | ปัจจุบันเป็น `self_reported` เสมอ |
| `recordedAt` | เวลา | เวลาที่กรอก |

## 4. `users/{uid}/state/pet` — สถานะสัตว์เลี้ยง

| ฟิลด์ | ความหมาย | มีประโยชน์กับงานวิจัยไหม |
|---|---|---|
| `totalFocusMinutes` | เวลาปลอดหน้าจอสะสมทั้งหมด | ✅ ใช้ได้ |
| `freeMinutesTotal` | เวลาสะสมเฉพาะโหมดอิสระ | ✅ ใช้ได้ |
| `freePointsAwarded` | แต้มโหมดอิสระที่จ่ายไปแล้ว | ✅ ใช้ได้ |
| `streakDays` | จำนวนวันที่ทำต่อเนื่อง | ✅ ใช้วัดความสม่ำเสมอ |
| `lastSessionDate` | วันที่ทำเซสชันล่าสุด | ✅ ใช้ดูว่าเลิกใช้เมื่อไหร่ |
| `level` · `exp` · `stage` | ความก้าวหน้าในเกม | ✅ ใช้วัดการมีส่วนร่วม |
| `isAlive` · `diedAt` · `bornAt` · `generation` | การอยู่รอดของสัตว์เลี้ยง | ✅ **ตัวชี้วัดการเลิกใช้ที่ดีมาก** |
| `hunger` · `happiness` · `energy` · `health` | ค่าสถานะ ณ เวลาที่บันทึก | ⚠️ เป็นค่า ณ ขณะนั้น ไม่ใช่ประวัติ |
| `coins` | เหรียญคงเหลือ | ไม่ค่อยมีประโยชน์ |
| `name` · `species` | ชื่อและสีที่ผู้ใช้ตั้ง | ไม่ใช่ข้อมูลวิจัย |
| `lastTickAt` · `lastFedTimestamp` · `lastFocusTimestamp` | เวลาที่ระบบใช้คำนวณ | ใช้ภายใน |

> `diedAt` มีค่า = ผู้เข้าร่วมคนนั้นหายไปเกิน ~2.7 วัน
> เป็นสัญญาณการหลุดจากงานวิจัยที่ตรวจจับได้โดยไม่ต้องถาม

## 5–7. ข้อมูลที่ไม่ได้ส่งออก

**`state/inventory`** — รายการไอเทมและจำนวน
**`state/achievements`** — เวลาที่ปลดล็อกความสำเร็จแต่ละอัน
**`state/push`** — token แจ้งเตือน, เวลาที่ต้องเตือนครั้งถัดไป, เวลาที่เตือนล่าสุด, ชื่อเบราว์เซอร์/ระบบปฏิบัติการ (120 ตัวอักษรแรก)
**`participantIds/{code}`** — uid ของเจ้าของรหัสและเวลาที่จอง

ทั้งหมดนี้อยู่ในฐานข้อมูลแต่สคริปต์ `export-research-data.mjs` ไม่ดึงออกมา
ถ้าต้องการใช้ในงานวิจัย บอกทีมพัฒนาให้เพิ่มคอลัมน์ได้

## 8. คอลัมน์ `source` — สำคัญที่สุดในการวิเคราะห์

ทุกตัวเลขบอกว่าได้มาอย่างไร **ห้ามรวมกันโดยไม่แยกดูก่อน**

| ค่า | ความหมาย | ความน่าเชื่อถือ |
|---|---|---|
| `web_timer_verified` | เว็บจับเวลาให้ ผู้ใช้ไม่ออกจากแท็บเลย | สูงสุดเท่าที่เว็บทำได้ |
| `web_timer_interrupted` | จับเวลาแต่ผู้ใช้สลับไปแท็บอื่นระหว่างทาง | ต่ำ ควรแยกหรือตัดออก |
| `self_reported` | ผู้ใช้กรอกเองจาก Digital Wellbeing | ต่ำ เป็นข้อมูลรายงานตนเอง |
| `android_usage_stats` | วัดจากแอป Android | สูงสุด (ยังไม่ได้ใช้) |

## 9. สิ่งที่ระบบ **ไม่** เก็บ

| ไม่เก็บ | เหตุผล |
|---|---|
| ชื่อจริง อีเมล รูปโปรไฟล์ | หนังสือยินยอมสัญญาไว้ว่าไฟล์วิเคราะห์จะไม่มี (Firebase Auth เก็บไว้แยก แต่สคริปต์ไม่ดึงออกมา) |
| รายชื่อแอปที่ผู้ใช้เปิดบนมือถือ | เว็บทำไม่ได้ |
| เวลาหน้าจอจริงจากระบบปฏิบัติการ | เว็บทำไม่ได้ (ดูข้อจำกัดในเอกสารหลัก) |
| ตำแหน่งที่อยู่ รายชื่อผู้ติดต่อ รูปภาพ | ไม่ขอสิทธิ์เหล่านี้เลย |
| การเปิด–ปิดแอปแต่ละครั้ง | **ยังไม่ได้เก็บ — ดูหัวข้อ 10** |
| หน้าจอที่ผู้ใช้เข้าชม | **ยังไม่ได้เก็บ — ดูหัวข้อ 10** |
| การให้อาหาร เล่นด้วย ซื้อของ | **ยังไม่ได้เก็บ — ดูหัวข้อ 10** |

## 10. ⚠️ ช่องว่างที่ควรรู้ก่อนวิเคราะห์

ถ้าคำถามวิจัยคือ "แอปนี้ทำให้คนลดเวลาหน้าจอได้ไหม" ข้อมูลที่มีอยู่ **เพียงพอแล้ว**

แต่ถ้าอยากตอบว่า "ผู้ใช้มีพฤติกรรมการใช้แอปอย่างไร" ยังขาดอยู่พอสมควร

| อยากรู้ | ตอบได้จากข้อมูลปัจจุบันไหม |
|---|---|
| ทำเซสชันบ่อยแค่ไหน นานเท่าไหร่ ช่วงเวลาไหน | ✅ ได้ จาก `sessions` |
| ทำต่อเนื่องกี่วัน เลิกใช้เมื่อไหร่ | ✅ ได้ จาก `streakDays` และ `lastSessionDate` |
| เวลาหน้าจอลดลงไหม | ✅ ได้ จาก `screenTimeDays` (แต่เป็นข้อมูลกรอกเอง) |
| เปิดแอปวันละกี่ครั้ง | ❌ **ไม่ได้** |
| ใช้เวลาอยู่ในแอปนานแค่ไหน | ❌ **ไม่ได้** |
| เข้าหน้าไหนบ่อยที่สุด | ❌ **ไม่ได้** |
| ให้อาหาร/เล่นด้วยบ่อยแค่ไหน | ❌ **ไม่ได้** (เห็นแค่ผลลัพธ์ในค่าสถานะ) |
| กดแจ้งเตือนแล้วกลับมาเปิดแอปไหม | ❌ **ไม่ได้** |
| เซสชันที่ยกเลิกก่อน 2 นาที | ❌ **ไม่ได้** ถูกทิ้งไปเลย |

### ถ้าจะเพิ่มการเก็บข้อมูล ต้องทำอะไรบ้าง

**ไม่สามารถเพิ่มเงียบ ๆ ได้** หนังสือยินยอมระบุรายการข้อมูลที่เก็บไว้ชัดเจน
การเก็บเพิ่มโดยไม่แจ้งคือการละเมิดความยินยอมที่ได้รับมา ขั้นตอนที่ถูกต้องคือ

1. เพิ่มรายการใหม่ในหัวข้อ "ระบบเก็บข้อมูลอะไรของท่านบ้าง" ใน `web/src/lib/consent.ts`
2. **เพิ่มเลขเวอร์ชัน** `CONSENT_VERSION` เช่น `2026-09-22.v2`
3. ผู้ที่ยินยอมเวอร์ชันเก่าไปแล้ว ต้องขอความยินยอมใหม่ หรือแยกวิเคราะห์ตามเวอร์ชัน
4. สคริปต์ export จะเตือนอัตโนมัติถ้าพบผู้เข้าร่วมยินยอมคนละเวอร์ชันกัน

**คำแนะนำ:** ถ้าจะเพิ่ม ให้ตัดสินใจ**ก่อน**เริ่มเก็บข้อมูลจริง เพราะการเพิ่มกลางคัน
จะทำให้ผู้เข้าร่วมกลุ่มแรกกับกลุ่มหลังมีข้อมูลไม่เท่ากัน ซึ่งวิเคราะห์รวมกันไม่ได้

## 11. วิธีดึงข้อมูลทั้งหมดออกมาดู

```bash
cd scripts
node export-research-data.mjs --key ./serviceAccount.json --out ./export
```

ได้ไฟล์ `participants.csv` · `sessions.csv` · `screentime.csv` · `daily_summary.csv`
รายละเอียดแต่ละไฟล์อยู่ใน [scripts/README.md](../scripts/README.md)

**ข้อควรระวังตอนนำเข้า SPSS หรือ pandas:** `screen_time_minutes` ที่เป็นช่องว่าง
แปลว่า **วันนั้นไม่ได้กรอก** ไม่ใช่ "ใช้หน้าจอ 0 นาที" ต้องตั้งเป็น missing value
ไม่อย่างนั้นค่าเฉลี่ยจะผิดทั้งหมด
