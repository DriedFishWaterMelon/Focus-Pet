**หนึ่งเอกสารต่อหนึ่งเซสชัน** นี่คือข้อมูลหลักของงานวิจัย

| ฟิลด์ | ชนิด | ความหมาย |
|---|---|---|
| `startTime` | เวลา | เวลาเริ่มเซสชัน |
| `endTime` | เวลา | เวลาจบเซสชัน |
| `actualMinutes` | ตัวเลข | ระยะเวลาที่ทำได้จริง |

| `completed` | จริง/เท็จ | ทำครบเป้าหรือไม่ (โหมดอิสระเป็นเท็จเสมอ) |
| `abandoned` | จริง/เท็จ | หยุดก่อน 2 นาที จึงไม่ได้รางวัลใด ๆ (`expEarned` และ `coinsEarned` เป็น 0) |
| `mode` | ข้อความ | `targeted` หรือ `free` |

| `coinsEarned` | ตัวเลข | เหรียญที่ได้ |
| `itemRewardName` | ข้อความ | ไอเทมที่ได้ (ถ้ามี) |

> **เซสชันที่สั้นกว่า 2 นาทีไม่ถูกบันทึกเลย** ทั้งที่ทำครบและที่ยกเลิก
> ถ้างานวิจัยต้องการนับความพยายามที่ล้มเหลวด้วย ต้องแก้โค้ดและแจ้งผู้เข้าร่วมใหม่

## 5. `users/{uid}/appVisits/{timestamp}` — การใช้งานตัวแอป

เพิ่มในหนังสือยินยอมเวอร์ชัน `2026-09-22.v2`
**เก็บเฉพาะผู้ที่ยินยอมเวอร์ชันนี้เท่านั้น** ผู้ที่ยินยอมเวอร์ชันก่อนหน้าจะไม่มีข้อมูลส่วนนี้
จนกว่าจะอ่านและยินยอมฉบับใหม่ในหน้าตั้งค่า

หนึ่งเอกสาร = หนึ่งครั้งที่เปิดแอป ไม่ใช่หนึ่งครั้งที่กดปุ่ม
ชื่อเอกสารคือเวลาที่เปิด (หน่วยมิลลิวินาที) ระบบจึงเขียนทับเอกสารเดิมระหว่างที่ยังเปิดค้างอยู่
แทนที่จะสร้างใหม่ทุกครั้งที่บันทึก

| ฟิลด์ | ชนิด | ความหมาย |
|---|---|---|
| `openedAt` | เวลา | เวลาที่เปิดแอป |
| `lastSeenAt` | เวลา | เวลาที่บันทึกล่าสุด |
| `durationSeconds` | ตัวเลข | อยู่ในแอปนานกี่วินาที |
| `openedFrom` | ข้อความ | `notification` = มาจากการแตะแจ้งเตือน, `direct` = เปิดเอง |
| `closed` | จริง/เท็จ | ปิดแอปเรียบร้อยหรือขาดการติดต่อไปเฉย ๆ |
| `screens` | ตาราง | นับจำนวนครั้งที่เข้าแต่ละหน้า: `home` `focus` `shop` `stats` `inventory` `settings` |
| `actions` | ตาราง | นับจำนวนครั้งที่ `feed` (ให้อาหาร) `pat` (เล่นด้วย) `purchase` (ซื้อของ) |
| `consentVersion` | ข้อความ | เวอร์ชันหนังสือยินยอมขณะที่บันทึก |

**ข้อควรรู้ตอนวิเคราะห์**

`durationSeconds` นับเฉพาะตอนที่แท็บอยู่หน้าจอ พอผู้ใช้สลับไปแอปอื่นระบบจะปิดการนับทันที
ตัวเลขนี้จึงเป็น "เวลาที่จ้องแอปนี้จริง ๆ" ไม่ใช่ "เวลาที่เปิดแท็บค้างไว้"

ระบบบันทึกทุก 2 นาทีระหว่างที่เปิดค้างอยู่ ไม่ได้รอจนปิดแอปแล้วค่อยบันทึกครั้งเดียว
เพราะเบราว์เซอร์ไม่รับประกันว่าจะให้โอกาสหน้าเว็บเขียนอะไรตอนถูกปิด
ถ้ารอ ครั้งที่ผู้ใช้ปิดแท็บไปเลยจะหายทั้งหมด ผลข้างเคียงคือครั้งที่ `closed` เป็นเท็จ
อาจมี `durationSeconds` ต่ำกว่าความจริงได้ไม่เกิน 2 นาที

**ไม่เก็บ** ลำดับการกด ข้อความที่พิมพ์ หรือเวลาที่กดแต่ละปุ่ม เก็บเป็นยอดรวมต่อครั้งที่เปิดเท่านั้น

## 6–8. ข้อมูลที่ไม่ได้ส่งออก

**`state/inventory`** — รายการไอเทมและจำนวน
**`state/achievements`** — เวลาที่ปลดล็อกความสำเร็จแต่ละอัน
**`state/push`** — token แจ้งเตือน, เวลาที่ต้องเตือนครั้งถัดไป, เวลาที่เตือนล่าสุด, ชื่อเบราว์เซอร์/ระบบปฏิบัติการ (120 ตัวอักษรแรก)
**`participantIds/{code}`** — uid ของเจ้าของรหัสและเวลาที่จอง

ทั้งหมดนี้อยู่ในฐานข้อมูลแต่สคริปต์ `export-research-data.mjs` ไม่ดึงออกมา
ถ้าต้องการใช้ในงานวิจัย บอกทีมพัฒนาให้เพิ่มคอลัมน์ได้

## 8. คอลัมน์ `source` — สำคัญที่สุดในการวิเคราะห์

ทุกตัวเลขบอกว่าได้มาอย่างไร **ห้ามรวมกันโดยไม่แยกดูก่อน**

| ค่า | ความหมาย | ความน่าเชื่อถือ |
|---|---|---|
| `web_timer_verified` | เว็บจับเวลาให้ ผู้ใช้ไม่ออกจากแท็บเลย | สูงสุดเท่าที่เว็บทำได้ |
| `web_timer_interrupted` | จับเวลาแต่ผู้ใช้สลับไปแท็บอื่นระหว่างทาง | ต่ำ ควรแยกหรือตัดออก |
| `self_reported` | ผู้ใช้กรอกเองจาก Digital Wellbeing | ต่ำ เป็นข้อมูลรายงานตนเอง |
| `android_usage_stats` | วัดจากแอป Android | สูงสุด (ยังไม่ได้ใช้) |

## 9. สิ่งที่ระบบ **ไม่** เก็บ

| ไม่เก็บ | เหตุผล |
|---|---|
| ชื่อจริง อีเมล รูปโปรไฟล์ | หนังสือยินยอมสัญญาไว้ว่าไฟล์วิเคราะห์จะไม่มี (Firebase Auth เก็บไว้แยก แต่สคริปต์ไม่ดึงออกมา) |
| รายชื่อแอปที่ผู้ใช้เปิดบนมือถือ | เว็บทำไม่ได้ |
| เวลาหน้าจอจริงจากระบบปฏิบัติการ | เว็บทำไม่ได้ (ดูข้อจำกัดในเอกสารหลัก) |
| ตำแหน่งที่อยู่ รายชื่อผู้ติดต่อ รูปภาพ | ไม่ขอสิทธิ์เหล่านี้เลย |
| ลำดับการกดปุ่มทีละครั้ง | เก็บเป็นยอดรวมต่อการเปิดแอปหนึ่งครั้ง ไม่ใช่รายเหตุการณ์ (ดูหัวข้อ 5) |
| ข้อความที่ผู้ใช้พิมพ์ | เก็บเฉพาะชื่อสัตว์เลี้ยง ซึ่งไม่ได้ส่งออกไปวิเคราะห์ |
| การใช้งานแอปของผู้ที่ยินยอมเวอร์ชันเก่า | ยังไม่ได้ยินยอมรายการนี้ ระบบจึงไม่เก็บจนกว่าจะยินยอมใหม่ |

## 10. ⚠️ ช่องว่างที่ควรรู้ก่อนวิเคราะห์

ถ้าคำถามวิจัยคือ "แอปนี้ทำให้คนลดเวลาหน้าจอได้ไหม" ข้อมูลที่มีอยู่ **เพียงพอแล้ว**

ตั้งแต่หนังสือยินยอมเวอร์ชัน `2026-09-22.v2` คำถามเรื่องพฤติกรรมการใช้แอป
ตอบได้เพิ่มอีกหลายข้อ แต่ **เฉพาะกับผู้ที่ยินยอมเวอร์ชันนี้** ตารางด้านล่างจึงมีคอลัมน์
บอกด้วยว่าคำถามนั้นตอบได้กับทุกคนหรือเฉพาะบางกลุ่ม

| อยากรู้ | ตอบได้ไหม | กับใคร |
|---|---|---|
| ทำเซสชันบ่อยแค่ไหน นานเท่าไหร่ ช่วงเวลาไหน | ✅ จาก `sessions` | ทุกคน |
| ทำต่อเนื่องกี่วัน เลิกใช้เมื่อไหร่ | ✅ จาก `streakDays` และ `lastSessionDate` | ทุกคน |
| เวลาหน้าจอลดลงไหม | ✅ จาก `screenTimeDays` (แต่เป็นข้อมูลกรอกเอง) | ทุกคน |
| เซสชันที่ยกเลิกก่อน 2 นาที | ✅ จาก `sessions.abandoned` | ทุกคน |
| เปิดแอปวันละกี่ครั้ง | ✅ นับแถวใน `app_visits.csv` ต่อวัน | เฉพาะ v2 |
| ใช้เวลาอยู่ในแอปนานแค่ไหน | ✅ จาก `duration_seconds` | เฉพาะ v2 |
| เข้าหน้าไหนบ่อยที่สุด | ✅ จากคอลัมน์ `screen_*` | เฉพาะ v2 |
| ให้อาหาร/เล่นด้วยบ่อยแค่ไหน | ✅ จากคอลัมน์ `action_*` | เฉพาะ v2 |
| กดแจ้งเตือนแล้วกลับมาเปิดแอปไหม | ✅ จาก `opened_from = notification` | เฉพาะ v2 |
| เปิดแอปตอนไหนของวัน | ✅ จาก `opened_at_iso` | เฉพาะ v2 |
| กดปุ่มไหนก่อนหลัง | ❌ ไม่ได้เก็บลำดับ ตั้งใจไม่เก็บ |  |

> **สำคัญ:** ก่อนรายงานตัวเลขจากคอลัมน์ "เฉพาะ v2" ต้องบอกด้วยว่ามาจากผู้เข้าร่วมกี่คน
> จากทั้งหมดกี่คน การนำไปหารด้วยจำนวนผู้เข้าร่วมทั้งหมดจะได้ค่าที่ต่ำกว่าความจริง
> `participants.csv` มีคอลัมน์ `consent_version` ไว้แยกกลุ่มนี้

### ถ้าจะเพิ่มการเก็บข้อมูลอีก ต้องทำอะไรบ้าง

ขั้นตอนนี้เคยใช้จริงมาแล้วครั้งหนึ่ง ตอนเพิ่มการเก็บข้อมูลการใช้งานแอป
(`2026-09-22.v1` → `2026-09-22.v2`) ทำแบบเดียวกันนี้ทุกครั้ง

**ไม่สามารถเพิ่มเงียบ ๆ ได้** หนังสือยินยอมระบุรายการข้อมูลที่เก็บไว้ชัดเจน
การเก็บเพิ่มโดยไม่แจ้งคือการละเมิดความยินยอมที่ได้รับมา ขั้นตอนที่ถูกต้องคือ

1. เพิ่มรายการใหม่ในหัวข้อ "ระบบเก็บข้อมูลอะไรของท่านบ้าง" ใน `web/src/lib/consent.ts`
2. **เพิ่มเลขเวอร์ชัน** `CONSENT_VERSION` เช่น `2026-09-22.v2`
3. ผู้ที่ยินยอมเวอร์ชันเก่าไปแล้ว ต้องขอความยินยอมใหม่ หรือแยกวิเคราะห์ตามเวอร์ชัน
4. เพิ่มเงื่อนไข `acceptsConsentVersion()` ในโค้ดที่เขียนข้อมูลใหม่ เพื่อให้ระบบ
   **หยุดเก็บเองโดยอัตโนมัติ** กับคนที่ยังไม่ได้ยินยอมเวอร์ชันใหม่ ไม่ใช่มาคัดออกทีหลัง
5. สคริปต์ export จะเตือนอัตโนมัติถ้าพบผู้เข้าร่วมยินยอมคนละเวอร์ชันกัน

**คำแนะนำ:** ถ้าจะเพิ่ม ให้ตัดสินใจ**ก่อน**เริ่มเก็บข้อมูลจริง เพราะการเพิ่มกลางคัน
จะทำให้ผู้เข้าร่วมกลุ่มแรกกับกลุ่มหลังมีข้อมูลไม่เท่ากัน ซึ่งวิเคราะห์รวมกันไม่ได้
