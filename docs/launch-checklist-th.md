## 🔴 ต้องทำก่อนส่งลิงก์ให้ผู้เข้าร่วมคนแรก

### 1. ใส่ VAPID key เพื่อเปิดระบบแจ้งเตือน

ระบบแจ้งเตือนสร้างเสร็จแล้ว แต่ยังไม่ทำงานจนกว่าจะใส่กุญแจ

1. เปิด [Console → Project settings → Cloud Messaging](https://console.firebase.google.com/project/focus-pet-g8/settings/cloudmessaging)
2. เลื่อนไปหัวข้อ **Web Push certificates** → กด **Generate key pair**
3. คัดลอกค่า **Key pair** ที่ได้
4. เปิดไฟล์ `web/.env` แล้ววางต่อท้ายบรรทัด

   ```
   VITE_FIREBASE_VAPID_KEY=<วางค่าที่คัดลอกมา>
   ```

5. สั่ง deploy ใหม่

   ```bash
   npm --prefix web run build
   firebase deploy --only hosting
   ```

ถ้ายังไม่ใส่ หน้าตั้งค่าจะขึ้นกรอบเหลืองเตือนทีมพัฒนาไว้ และปุ่มเปิดแจ้งเตือนจะไม่ทำงาน
ตัวแอปส่วนอื่นใช้ได้ปกติทุกอย่าง

### 2. ตั้งเวลาให้สคริปต์ส่งแจ้งเตือนรันอัตโนมัติ

```bash
cd scripts
node send-reminders.mjs --key ./serviceAccount.json --dry-run   # ลองดูก่อนว่าจะส่งให้ใคร
node send-reminders.mjs --key ./serviceAccount.json             # ส่งจริง
```

ตั้ง Windows Task Scheduler ให้รันวันละ 1 ครั้ง (แนะนำช่วงเย็น ประมาณ 19:00)
สคริปต์มีกติกาในตัวอยู่แล้ว

- ไม่ส่งซ้ำคนเดิมภายใน 20 ชั่วโมง
- ไม่ส่งช่วง 22:00–08:00
- ไม่ส่งให้คนที่สัตว์เลี้ยงเสียชีวิตแล้ว
- ล้าง token ที่ใช้ไม่ได้ออกอัตโนมัติ

### 3. แก้ข้อความ SAS-SV / PSQI หรือบันทึกเป็นข้อจำกัด

ทีมเลือกแนวทาง **(ข)** คือใช้ฉบับร่างไปก่อน ดังนั้น**ต้องเขียนไว้ในรายงาน**
หัวข้อข้อจำกัดของงานวิจัยว่า

> แบบวัด SAS-SV และ PSQI ที่ใช้ในการศึกษานี้เป็นฉบับแปลภาษาไทยที่คณะผู้วิจัย
> จัดทำขึ้นเอง ยังไม่ได้ผ่านกระบวนการตรวจสอบความตรงและความเที่ยง
> จึงไม่สามารถเทียบคะแนนกับเกณฑ์มาตรฐานสากลหรือกับงานวิจัยอื่นได้โดยตรง
> ผลที่รายงานจึงควรตีความในเชิงเปรียบเทียบก่อน–หลังภายในกลุ่มตัวอย่างเดียวกันเท่านั้น

ถ้าหาฉบับแปลมาตรฐานได้ภายหลัง แก้ข้อความในฟอร์มโดยตรงได้เลย ไม่ต้องรันสคริปต์สร้างฟอร์มใหม่
และ entry ID ของช่องรหัสจะไม่เปลี่ยน ตราบใดที่ไม่ลบแล้วสร้างช่องนั้นใหม่

## 🟡 ข้อความที่ควรใช้ตอนชวนผู้เข้าร่วม

> **ขอเชิญร่วมโครงงานวิจัย Focus Pet**
>
> เปลี่ยนเวลาที่ไม่ได้ใช้มือถือ ให้กลายเป็นความก้าวหน้าของสัตว์เลี้ยงเสมือน
> ใช้เวลาประมาณ 4 สัปดาห์
>
> 👉 https://focus-pet-g8.web.app
>
> **สิ่งที่ต้องทำ**
> 1. เปิดลิงก์ แล้ว **เข้าสู่ระบบด้วย Google** (สำคัญ — ดูเหตุผลด้านล่าง)
> 2. อ่านและกดยินยอมเข้าร่วมงานวิจัย
> 3. กด **"เพิ่มลงหน้าจอโฮม"** เพื่อใช้งานเหมือนแอปจริง
> 4. เปิดการแจ้งเตือนในหน้าตั้งค่า
> 5. กดปุ่ม **"ทำแบบสอบถาม"** ในแอป ทำรอบแรก (เลือก "ก่อนเริ่มใช้แอป")
> 6. ใช้งานต่อเนื่อง 4 สัปดาห์ แล้วทำแบบสอบถามอีกรอบ (เลือก "หลังใช้ครบ 4 สัปดาห์")
>
> ⚠️ **กรุณาเข้าสู่ระบบด้วย Google ไม่ใช่โหมดผู้เยี่ยมชม**
> เพราะโหมดผู้เยี่ยมชมจะเสียข้อมูลทั้งหมดถ้าล้างข้อมูลเบราว์เซอร์
> ซึ่งแปลว่าข้อมูลของท่านตลอด 4 สัปดาห์จะหายไป
>
> การเข้าร่วมเป็นไปโดยสมัครใจ ถอนตัวได้ตลอดเวลา

## 🟢 ความเสี่ยงที่ทีมควรเฝ้าระหว่างเก็บข้อมูล

| ความเสี่ยง | ผลถ้าเกิด | วิธีลด |
|---|---|---|
| ผู้เข้าร่วมใช้โหมดผู้เยี่ยมชมแล้วล้างเบราว์เซอร์ | ข้อมูลคนนั้นหายทั้งหมด | ย้ำให้ใช้ Google sign-in ในข้อความชวน |
| ลืมเปิดแอป สัตว์เลี้ยงเสียชีวิต | อาจเลิกใช้กลางคัน | เปิดระบบแจ้งเตือน + เตือนในกลุ่มทุก 2–3 วัน |
| ลืมกรอกเวลาหน้าจอรายวัน | ข้อมูลรายวันขาดช่วง | เตือนในกลุ่มพร้อมกับข้อบน |
| ลืมทำแบบสอบถามรอบหลัง | จับคู่ก่อน–หลังไม่ได้ | เตือนล่วงหน้า 2 วันก่อนครบ 4 สัปดาห์ |
| ไม่ได้ใส่รหัสผู้เข้าร่วม | ข้อมูลคนนั้นถูกข้ามตอนวิเคราะห์ | ระบบออกรหัสให้เองแล้ว แต่ควรสุ่มตรวจสัปดาห์แรก |

**สุ่มตรวจสัปดาห์แรก** รัน `npm run export` ใน `scripts/` แล้วดูว่า

- จำนวนผู้เข้าร่วมตรงกับที่ชวนมาหรือไม่
- มีใครยังไม่มีรหัส (จะถูกนับอยู่ในบรรทัด "ข้ามผู้ที่ยังไม่ได้ยินยอมหรือไม่มีรหัส")
- สัดส่วนเซสชันที่ "ถูกขัดจังหวะ" สูงผิดปกติหรือไม่

## 📋 ลำดับการลงมือวันนี้

1. ใส่ VAPID key แล้ว deploy ใหม่ (5 นาที)
2. ทดสอบด้วยตัวเองบนมือถือจริง 1 รอบเต็ม — สมัคร ยินยอม เปิดแจ้งเตือน ทำเซสชัน 2 นาที กดทำแบบสอบถาม (10 นาที)
3. รัน `send-reminders.mjs --dry-run` ดูว่าอ่านข้อมูลได้ (2 นาที)
4. แก้ข้อความชวนเข้าร่วมให้ตรงกับช่องทางที่จะใช้ส่ง (5 นาที)
5. ส่งให้สมาชิกทีมลองก่อน 1 วัน แล้วค่อยเปิดให้ผู้เข้าร่วมภายนอก

ข้อ 5 ถ้าเวลาไม่พอจริง ๆ ข้ามได้ แต่**ข้อ 2 ห้ามข้าม** — ยังไม่มีใครใช้แอปนี้จบครบทั้งขั้นตอนบนมือถือจริงเลยสักคน
