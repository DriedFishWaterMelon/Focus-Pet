# เครื่องมือดึงข้อมูลวิจัย

สคริปต์สำหรับทีมวิจัยดึงข้อมูลผู้เข้าร่วมทุกคนออกมาเป็น CSV เพื่อนำไปวิเคราะห์

## ทำไมต้องมีสคริปต์นี้

`firestore.rules` ล็อกให้ผู้ใช้แต่ละคนเห็นได้เฉพาะข้อมูลของตัวเอง ซึ่งถูกต้องในแง่จริยธรรมการวิจัย
แต่ผลคือ **หน้าเว็บดึงข้อมูลรวมของทุกคนไม่ได้** ปุ่ม export ในหน้าสถิติได้เฉพาะข้อมูลของคนที่กดเท่านั้น

สคริปต์นี้รันด้วย service account ซึ่งข้าม security rules ได้ จึงเป็นทางเดียวที่จะรวบรวมชุดข้อมูลทั้งหมด
**รันจากเครื่องของทีมวิจัยเท่านั้น ห้าม deploy ขึ้นเว็บ**

## ติดตั้ง (ทำครั้งเดียว)

```bash
cd scripts
npm install
```

### สร้าง service account key

1. เปิด https://console.firebase.google.com/project/focus-pet-g8/settings/serviceaccounts/adminsdk
2. กด **Generate new private key** → **Generate key**
3. เซฟไฟล์ JSON ไว้ที่ `scripts/serviceAccount.json`

> ⚠️ ไฟล์นี้เปิดสิทธิ์เต็มกับฐานข้อมูล **ห้าม commit ขึ้น git และห้ามส่งในแชต**
> ใส่ไว้ใน `.gitignore` ให้แล้ว ถ้าหลุดให้กด revoke ทันทีในหน้า Console เดิม

## ใช้งาน

```bash
cd scripts
npm run export
```

หรือระบุ path เอง

```bash
node export-research-data.mjs --key ./serviceAccount.json --out ./export
```

| Flag | ความหมาย |
|---|---|
| `--key <path>` | ไฟล์ service account (จำเป็น) |
| `--out <dir>` | โฟลเดอร์ผลลัพธ์ (ค่าเริ่มต้น `./export`) |
| `--all` | รวมผู้ใช้ที่ยังไม่ได้ใส่รหัสผู้เข้าร่วมด้วย |

ค่าเริ่มต้นจะ **ข้ามคนที่ยังไม่ได้ยินยอมหรือยังไม่มีรหัส** เพื่อไม่ให้คนที่แค่เข้ามาลองเล่นปนเข้าไปในชุดข้อมูลวิจัย

> **รหัสผู้เข้าร่วมออกโดยแอป ไม่ใช่ทีมวิจัย**
> เดิมทีมต้องแจกรหัสเป็นกระดาษแล้วให้ผู้เข้าร่วมพิมพ์เอง ซึ่งสับสนและเสี่ยงกรอกซ้ำกัน
> ตอนนี้แอปออกรหัสรูปแบบ `FP-XXXXX` ให้อัตโนมัติตอนกดยินยอม แล้วผู้เข้าร่วม
> **คัดลอกรหัสไปกรอกในแบบสอบถาม** (Google Form) เอง
> ทีมจึงจับคู่ข้อมูลด้วยรหัสในคอลัมน์ `participant_id` กับรหัสที่ผู้เข้าร่วมกรอกในฟอร์ม

## ไฟล์ที่ได้

| ไฟล์ | หนึ่งแถวคือ | ใช้ทำอะไร |
|---|---|---|
| `participants.csv` | ผู้เข้าร่วม 1 คน | ข้อมูลภาพรวม จำนวนเซสชัน สถานะสัตว์เลี้ยง |
| `sessions.csv` | เซสชันปลอดหน้าจอ 1 ครั้ง | ข้อมูลดิบระดับเซสชัน |
| `screentime.csv` | เวลาหน้าจอ 1 วัน | ข้อมูลดิบที่ผู้เข้าร่วมกรอก |
| `daily_summary.csv` | ผู้เข้าร่วม × วัน | **ตารางหลักสำหรับทำสถิติ** |
| `surveys.csv` | คำตอบแบบสอบถาม 1 ชุด | สร้างเมื่อมีข้อมูล SAS-SV / PSQI |

### สองเรื่องที่ต้องรู้ก่อนวิเคราะห์

**1. คอลัมน์ `source` สำคัญที่สุด**

ทุกแถวบอกว่าตัวเลขนั้นได้มาอย่างไร ห้ามรวมกันดื้อ ๆ

| ค่า | ความหมาย | น้ำหนักความน่าเชื่อถือ |
|---|---|---|
| `web_timer_screen_off` | หน้าเว็บถูกซ่อนตลอดเซสชัน = วางมือถือไว้จริง | สูงสุด (บนเว็บ) |
| `web_timer_screen_on` | ผู้ใช้เปิดหน้าจอค้างไว้ = ยังจ้องจออยู่ | ต่ำ ควรแยกหรือตัดออก |
| `self_reported` | ผู้ใช้กรอกเองจาก Digital Wellbeing | ต่ำ เป็น self-report |
| `android_usage_stats` | วัดจากแอป Android จริง | สูงสุด (ยังไม่ได้ใช้) |

ใน `daily_summary.csv` คอลัมน์ `focus_minutes` **ไม่รวม**เซสชันที่ถูกขัดจังหวะแล้ว
ส่วนจำนวนครั้งที่ถูกขัดอยู่ในคอลัมน์ `interrupted_count` แยกไว้ให้ตัดสินใจเอง

**2. ช่องว่างไม่เท่ากับศูนย์**

`screen_time_minutes` ที่เป็นช่องว่างแปลว่า **วันนั้นผู้เข้าร่วมไม่ได้กรอกข้อมูล**
ไม่ใช่ "ใช้หน้าจอ 0 นาที" ถ้าเผลอแทนค่าว่างด้วย 0 ตอนนำเข้า SPSS หรือ pandas
ผลวิเคราะห์จะผิดทั้งหมด ให้ตั้งเป็น missing value

## ความเป็นส่วนตัว

ไฟล์ที่ได้**ไม่มีชื่อจริงและอีเมล**ของผู้เข้าร่วม มีแค่

- `participant_id` — รหัสนิรนามที่แอปออกให้อัตโนมัติ (รูปแบบ `FP-XXXXX`)
- `uid` — รหัสภายในของ Firebase ไว้ย้อนกลับไปตรวจสอบข้อมูลเฉพาะราย

จึงส่งไฟล์ให้อาจารย์ที่ปรึกษาหรือแนบในรายงานได้โดยไม่เปิดเผยตัวตน

## ทดสอบโดยไม่แตะข้อมูลจริง

อยากเห็นหน้าตาไฟล์ผลลัพธ์ก่อนมีผู้เข้าร่วมจริง ให้รันกับ emulator

```bash
firebase emulators:exec --only firestore --project focus-pet-g8 \
  "node scripts/seed-emulator.mjs scripts/serviceAccount.json && node scripts/export-research-data.mjs --key scripts/serviceAccount.json --out ./export-test"
```

`seed-emulator.mjs` จะสร้างผู้เข้าร่วมปลอม 3 คนให้ และมันจะ**ปฏิเสธรันถ้าไม่ได้ชี้ไปที่ emulator**
เพื่อไม่ให้ข้อมูลปลอมหลุดลงฐานข้อมูลจริง

## สร้างแบบสอบถาม Google Forms อัตโนมัติ

ไฟล์ `create-google-form.gs` เป็นสคริปต์ Google Apps Script ที่สร้างแบบสอบถาม
ทั้งชุดให้อัตโนมัติ ไม่ต้องสร้างทีละข้อด้วยมือ

**วิธีใช้**

1. เปิด https://script.google.com → **New project**
2. ลบโค้ดตัวอย่างออก แล้ววางเนื้อหาไฟล์ `create-google-form.gs` ทั้งไฟล์
3. กด Save แล้วเลือกฟังก์ชัน `createFocusPetForm` → กด **Run**
4. อนุญาตสิทธิ์ในครั้งแรก (จะขึ้นเตือนว่าแอปยังไม่ผ่านการตรวจสอบ เป็นเรื่องปกติ
   เพราะเป็นสคริปต์ที่ทีมเขียนเอง กด Advanced → Go to ... ต่อได้)
5. ดูผลใน **Execution log** จะได้ลิงก์ฟอร์ม ลิงก์ชีต และ **PREFILL URL**

**สิ่งที่สคริปต์สร้างให้**

| ตอน | เนื้อหา | สถานะ |
|---|---|---|
| 1 | รหัสผู้เข้าร่วม + รอบการตอบ (ก่อน/หลัง) | พร้อมใช้ |
| 2 | ข้อมูลทั่วไป | พร้อมใช้ |
| 3 | SAS-SV 10 ข้อ มาตรวัด 6 ระดับ | **ต้องแทนข้อความด้วยฉบับแปลไทยที่ผ่านการตรวจสอบ** |
| 4 | PSQI 19 ข้อ | **ต้องแทนข้อความด้วยฉบับแปลไทยที่ผ่านการตรวจสอบ** |
| 5 | ความพึงพอใจ 9 ข้อ | พร้อมใช้ (ตรงตามภาคผนวกข้อเสนอโครงงาน) |

ช่องรหัสผู้เข้าร่วมตั้ง **response validation** ไว้แล้วด้วยรูปแบบ
`^FP-[2-9A-HJKMNP-TV-Z]{5}$` ซึ่งตรงกับตัวสร้างรหัสในแอปพอดี
ผู้ตอบจึงกรอกรหัสผิดรูปแบบไม่ได้ตั้งแต่ต้นทาง

**ฟอร์มที่สร้างแล้ว (ใช้งานจริง)**

| | |
|---|---|
| ลิงก์ฟอร์ม | https://docs.google.com/forms/d/e/1FAIpQLScI0bdP-7T1BJbvjPP0v5I8Yp2y20L6uGjEjvH_N3O_zlxTlw/viewform |
| Entry ID ของช่องรหัส | `entry.1049877445` |
| ต่อเข้าแอปแล้ว | `web/src/lib/survey.ts` |

ผู้เข้าร่วมไม่ต้องเปิดลิงก์นี้เอง — ในแอปมีปุ่ม **"ทำแบบสอบถาม"** ทั้งในหน้าตั้งค่า
และหน้าสถิติ กดแล้วเปิดฟอร์มพร้อมกรอกรหัสให้อัตโนมัติ

**สิ่งที่ต้องส่งกลับให้ทีมพัฒนา**

บรรทัด `PREFILL URL:` ใน Execution log — ในลิงก์นั้นมีเลข `entry.xxxxxxxxx`
ซึ่งใช้ทำปุ่ม "ทำแบบสอบถาม" ในแอปที่เปิดฟอร์มพร้อมกรอกรหัสให้อัตโนมัติ

**การจับคู่ข้อมูลตอนวิเคราะห์**

ดาวน์โหลดชีตคำตอบเป็น CSV แล้ว join กับไฟล์จาก `npm run export` ด้วยคอลัมน์
`participant_id` และแยกรอบด้วยคอลัมน์รอบการตอบ (pre/post)

> **ไม่ใช้อีเมลจับคู่โดยเด็ดขาด** หนังสือยินยอมระบุไว้ว่าข้อมูลที่นำไปวิเคราะห์
> จะไม่มีอีเมลของผู้เข้าร่วม และผู้ที่เข้าใช้แบบผู้เยี่ยมชมก็ไม่มีอีเมลอยู่แล้ว
